# Bundle branch (jim-dot-tennis)

Branch `bundle` builds the image `ghcr.io/jameshartt/courthive-server` for
the jim-dot-tennis CourtHive bundle. It is the latest upstream
CourtHive/competition-factory-server at the commit in `bundle/UPSTREAM`
plus the small set of changes below, and nothing else. It is not built from
`jim-tennis-deploy`: that branch carries jim.tennis-only tooling (Parks Cup
import, plate and score-entry scripts, docs) that stays out of the bundle.

This is not an official CourtHive build.

## What the branch carries, and why

1. **No `link:` overrides** (`pnpm-workspace.yaml`, `pnpm-lock.yaml`).
   Upstream overrides `tods-competition-factory`, `@courthive/provider-config`
   and `@courthive/i18n` to sibling checkouts (`link:../factory` and so on).
   The image is built from published packages, so the overrides are removed
   and the lockfile is regenerated with the declared pnpm against the npm
   registry. `bundle/check-links.mjs` fails the build if any come back.
2. **Bundle files**, none of which change server behaviour:
   - `Dockerfile`, `.dockerignore`: the image. Node 26 Alpine; corepack is
     installed explicitly (Node 25+ no longer ships it) and fetches the
     `packageManager` pnpm. The runtime stage has production dependencies
     only, `build/` (compiled server; `nest build` copies the migration SQL
     into `build/src/storage/postgres/migrations`), `i18n/` (generated by
     `src/scripts/sync-i18n.mjs` from `@courthive/i18n`; the server reads it
     from `<cwd>/i18n` or `I18N_DIR`), `src/scripts/admin-user.mjs`, and
     `/licenses` (upstream `LICENSE`, `NOTICE`, third-party licences). Runs as
     `node`; `CMD node build/src/main.js`; health check on `/factory/version`.
   - `bundle/check-links.mjs`: the `link:` guard.
   - `bundle/third-party-licenses.mjs`: writes `/licenses/THIRD-PARTY-LICENSES.txt`
     from the installed packages.
   - `bundle/UPSTREAM`: upstream repository and commit (labels and NOTICE).
   - `bundle/build.sh`: local build under the final image name.
   - `.github/workflows/bundle-image.yml`: guard, lint, type check, image;
     pushes to GHCR on a `bundle-v<upstream version>-jdt.<n>` tag. DRAFT,
     never run.

No server source is patched. Old `jim-tennis-deploy` patches that were
reviewed and dropped for this base:

- `c230b02e` (save tournaments without `parentOrganisation`): only the Parks
  Cup staged import needed it; TMX always saves under a provider.
- `1de38a02` (remove federation-data module and `link:` overrides): upstream
  retired the module itself (66880e4c); the override removal is item 1.
- `98fe82c5` (copy migration SQL into the image): upstream now resolves
  migrations from `__dirname` and `nest build` copies them into `build/`.
- `62fde118` (copy generated `i18n/` into the image): still needed, done in
  the `Dockerfile`, not as a patch.
- The old `Dockerfile` (`91c5e302`): replaced by this branch's.

## Build

    bundle/build.sh 1     # clean tree required; tags <upstream version>-jdt.1

Nothing is pushed. The image needs at least `APP_NAME`, `JWT_SECRET`,
`STORAGE_PROVIDER=postgres`, `PG_*` and `REDIS_*`; it applies all
migrations itself on an empty database at boot. First administrator, after
the first boot:

    docker compose exec <service> node src/scripts/admin-user.mjs create -e <email> -p <password>

## Moving to a newer upstream

1. `git fetch upstream`, then start a new branch from the new upstream
   commit (do not rebase onto old fork history).
2. Cherry-pick the bundle-files commit. Re-apply item 1: delete the
   `link:` lines `node bundle/check-links.mjs` names and regenerate the
   lockfile with the declared pnpm inside Docker:

       docker run --rm -v "$PWD":/app -w /app -e CI=true node:<nvmrc>-alpine \
         sh -c 'npm i -g corepack && corepack enable && pnpm install --lockfile-only --ignore-scripts'

   Check the lockfile diff only swaps the `link:` entries for registry
   versions and has no `@pnpm/exe` block.
3. Re-check what the image assumes: the Node version in `.nvmrc`, the built
   entry file (`build/src/main.js`), that migrations land in `build/`, that
   `i18n/` is still read from the working directory, and that
   `src/scripts/admin-user.mjs` still exists and only needs production
   dependencies.
4. Update `bundle/UPSTREAM`, this file, and the action versions in the
   workflow (follow upstream's `ci.yml`).
5. Build, then boot against an empty Postgres and against a copy of the
   previous database; read the migrations added since the last base for
   steps that need a script (`scripts/backfill-*.mjs` in the past).
